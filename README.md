# UniCrossGait

Official reference code for **“UniCrossGait: Unified Cross-Modal Gait
Recognition Based on Knowledge Distillation”**, published in *IEEE
Transactions on Multimedia* (TMM), 2026.

[[Paper](https://doi.org/10.1109/TMM.2026.3664966)]
[[IEEE Xplore](https://ieeexplore.ieee.org/document/11396985)]
[[OpenGait](https://github.com/ShiqiYu/OpenGait)]
[[中文说明](README_zh-CN.md)]

> **Release scope.** This is a compact, paper-oriented extension for OpenGait,
> not a standalone fork or a one-command reproduction package. It contains the
> core model, losses, protocol evaluator, and configuration templates. Dataset
> preprocessing, licensed data, trained weights, and an exact environment image
> are not distributed. Minor adaptation may be needed for newer OpenGait APIs.

## Method at a glance

UniCrossGait trains in two stages:

1. A multimodal teacher fuses camera silhouettes and LiDAR depth images with
   bidirectional cross-attention.
2. The frozen teacher transfers its shared representation to the camera and
   depth students. The students share `SeparateFCs` and `SeparateBNNecks` and
   are optimized with DFI, IntraC, InterC, dynamic Distillation Balancing, a
   linear Warm-up operator, and bidirectional cross-modal triplet loss.

Only the two student branches are needed at inference. See
[docs/METHOD.md](docs/METHOD.md) for the equation-to-code mapping.

## Quick integration

Start from a clean [OpenGait](https://github.com/ShiqiYu/OpenGait) checkout.
Preview the overlay first, then apply it:

```bash
python scripts/install_into_opengait.py /path/to/OpenGait
python scripts/install_into_opengait.py /path/to/OpenGait --apply
```

The installer copies only the UniCrossGait extension files and configurations.
It also registers the evaluator with one import in OpenGait's
`evaluation/evaluator.py`. Existing files are not overwritten unless `--force`
is explicitly supplied. Manual integration is described in
[docs/INTEGRATION.md](docs/INTEGRATION.md).

Before training:

- prepare aligned 64×64 silhouette and LiDAR depth-image sequences;
- set `dataset_root`, `dataset_partition`, and `data_in_use` in both YAML files;
- verify that the selected input order agrees with `depth_input_index: 0` and
  `camera_input_index: 1`;
- use `class_num: 250` for the paper's SUSTech1K training split.

## Two-stage training

Commands below are examples for four GPUs and follow OpenGait's CLI. Run them
from the OpenGait repository after installing this overlay.

```bash
# Stage 1: multimodal teacher
CUDA_VISIBLE_DEVICES=0,1,2,3 \
torchrun --nproc_per_node=4 opengait/main.py \
  --cfgs configs/unicrossgait/unicrossgait_sustech1k_teacher.yaml \
  --phase train

# Stage 2: edit model_cfg.teacher_checkpoint first, then distill both students
CUDA_VISIBLE_DEVICES=0,1,2,3 \
torchrun --nproc_per_node=4 opengait/main.py \
  --cfgs configs/unicrossgait/unicrossgait_sustech1k_student.yaml \
  --phase train
```

For evaluation, set the student config's `restore_hint` to a checkpoint path or
iteration accepted by your OpenGait version, then use `--phase test`.

## Important implementation notes

- The supplied research file `PointGait.py` mixed the main method with several
  commented ablations. This release separates the final paper path from those
  experiments. In particular, DFI is cosine-direction imitation, InterC uses
  max pooling over parts, and logit distillation is not part of the default
  method (Sec. III-D and Table V).
- The paper's compact stage-2 objective in Eq. (28) lists distillation and
  cross-modal triplet loss. The authors' training snapshot additionally uses
  student identity classification through the shared BNNecks. The reference
  student YAML keeps this author-code behavior with `use_student_ce: true` and
  documents the switch; set it to `false` for a literal Eq. (28) path.
- The DB factors intentionally cross-weight the branches: 3D confidence sets
  the 2D weight and 2D confidence sets the 3D weight. Their range is
  `(0.5, 0.8808)`.
- The teacher remains in `eval()` mode during stage 2, including after OpenGait
  calls `train(True)`. This prevents frozen BatchNorm and Dropout state drift.
- Configuration files are templates because OpenGait preprocessing file names
  and `data_in_use` masks are installation-specific.

See [docs/REPRODUCIBILITY.md](docs/REPRODUCIBILITY.md) for the exact paper
settings, explicit assumptions, and validation boundaries.
