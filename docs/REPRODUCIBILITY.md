# Reproducibility scope and settings

This repository is an auditable reference release. It aims to make the paper's
core algorithm unambiguous while avoiding redistribution of an old OpenGait
workspace containing build products, machine-specific paths, unrelated models,
and experimental branches. It has not been advertised as a bit-exact,
end-to-end reproduction package.

## Settings stated in the paper

| Item | Stage 1: teacher | Stage 2: students |
| --- | --- | --- |
| Training length | 40,000 | 40,000 |
| Optimizer | Adam | Adam |
| Initial LR | 0.001 | 0.001 in reference template |
| Adam betas | `(0.99, 0.999)` | `(0.9, 0.999)` |
| Weight decay | `5e-4` | `5e-4` |
| LR schedule | MultiStepLR at 20k/30k, gamma 0.1 | same reference schedule |
| Hardware reported | 4× RTX 3090 | 4× RTX 3090 |
| Input | aligned 64×64 silhouettes + depth images | same |

The paper calls the 40,000 units “epochs”; OpenGait's engine and public author
logs use iteration-based schedules, so the YAML expresses them as iterations.
The stage-2 learning rate schedule is kept consistent with the author setup; it
is a template choice where the paper is less explicit than for stage 1.

## Dataset splits stated in the paper

| Dataset | Train | Test |
| --- | ---: | ---: |
| SUSTech1K | 250 identities / 6,011 sequences | 800 identities / 19,228 sequences |
| FreeGait | 500 identities / 5,000 sequences | 695 identities / 6,921 sequences |

Obtain datasets from their maintainers and comply with their licenses. This
repository does not include data, partition JSON files, or preprocessing code
whose correctness cannot be established from the supplied research snapshot.

## Paper-final choices versus research snapshot

| Topic | Paper-final reference | Intermediate snapshot residue |
| --- | --- | --- |
| Feature imitation | cosine direction (DFI) | selectable L2/cosine/KL and active logit-KD ablation |
| InterC holistic feature | max over parts | mean over parts in an older loss file |
| Student heads | shared FCs and BNNecks | additional `CommonSpaceShifting` and adaptors |
| Final KD | DFI + IntraC + InterC | several mutually exclusive commented branches |
| Warm-up | 0.1 → 1.5 over 40k, clamped | older helper/defaults varied across experiments |
| Runtime behavior | frozen teacher always in eval mode | `BaseModel.train(True)` could re-enable teacher Dropout/BN |
| Evaluation | return features to an evaluator | hard-coded `.npy` paths and forced process exit |

## Explicit reference choices

- `bin_num: [16]`, ResNet9 channel widths `[64,128,256,512]`, 512→256
  `SeparateFCs`, eight attention heads, 10 sampled frames, and batch `[16,8]`
  follow the architecture/configuration visible in the author materials.
- The two directional triplet terms have weight 0.5 each, forming a directional
  mean for the single `L_tri_cross` term in Eq. (28).
- `use_student_ce: true` follows the supplied author-code path. Disable it to
  isolate the compact Eq. (28) objective.
- The source DB computation is differentiable, represented by
  `detach_balance: false`. Set it to true for a stop-gradient ablation.
- Input file masks are deliberately not guessed from private preprocessing.
  The YAML's two-entry mask is a contract for a clean two-file layout and must
  be edited when a sequence directory contains additional representations.

## Validation status for this release

Performed in the packaging environment:

- all Python source was parsed with Python 3.8 grammar compatibility;
- both YAML files and `CITATION.cff` were parsed and their key invariants were
  checked;
- local Markdown links and the installer's dry-run/apply/idempotent behavior
  were checked;
- the release tree was scanned for machine-specific absolute paths, compiled
  artifacts, caches, and likely credentials.

`tests/test_core_math.py` covers warm-up endpoints, DB direction/range, DFI
scale invariance, and affinity matrix shapes/properties. It was not executed in
the packaging environment because PyTorch and pytest were not installed there;
run it inside the target OpenGait environment before training.

End-to-end model training is intentionally outside this release boundary
because the corresponding prepared datasets, partitions, environment, and
checkpoints were not supplied. Reported paper numbers should not be interpreted
as results regenerated by these files.
